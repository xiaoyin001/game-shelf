# ADR-0025：提交绑定的pre-push防漏检门禁

状态：采用（2026-10-23，门禁功能与Windows运行器22项、真实Git hook拒绝路径通过，已安装本仓库hook；最终SHA完整验收记录由提交后命令生成，不预填）。完成 [ADR-0023](0023-shared-ci-preflight.md) 第7项，共用运行器已在f361fd9独立提交，不把新增门禁预填为已通过。

授权流程更新：2026-10-26的 [ADR-0030](0030-standing-push-consent.md) 依据owner明确要求，以本仓库普通快进Push持续授权替代本文当时的逐次询问；技术门禁/时效/危险操作例外不变。以下历史决定与当时验收事实保留。

## 背景
仅提供共用入口仍会漏执行，或用上个commit/候选tree/单个job的通过申请Push。用户连续三次遇到推送后才失败，必须让缺少完整最终提交证据时自动拒绝，且保留每次Push的owner授权。

## 比较
- 只更新AGENTS/技能：保留为流程要求，但不足以阻止漏跑，不作为完整方案。
- 每次git push时隐式跑十几分钟全套：推送意图与资源操作混在一起，失败难定位，不能提前向owner展示最终证据，不采用。
- 完整验证自动生成提交绑定记录，pre-push只做快速只读校验：采用。门禁防误用，不宣称能阻止用户故意改报告或`--no-verify`。

## 决定
1. 继续使用唯一`npm run verify:ci`：只有干净HEAD、source完整+playable完整及额外新DB全浏览器全部通过，并确认回收后，才生成本地忽略目录中的推送验收记录。候选、prepare、单job和失败都不能产生有效记录；不新增重复的“另一套全验收命令”。
2. 本地默认两job的preflight是推送充分证据，包含额外浏览器轮与27s余量；Actions单job仍执行全部原回归一次，硬上限30s，不重复额外压力轮，也不把本地余量阈值当成远端业务失败条件。理由：本机完整playable实测642.4s已接近11分钟运行部分，给远端无必要地加一整轮会再引入总预算风险。比较保留云端双轮与本地更严格、云端原完整一轮，采用后者；环境、完整test:ci和原断言一致，单job结果绝不能生成推送记录。10/12/25分钟、真实浏览器30秒/零重试不改变。
3. 记录绑定commit/tree、origin的规范仓库身份、完整报告路径/SHA256、配置与配方hash、结束时间。报告必须包含实际SDK/CGO/资源、完整命令计划、两轮浏览器≥19且≤27s/零重试/无跳过，以及正常/故障/额外轮scope的零残留。命令计划由运行器和校验器共享，防止静默省略race或test:ci。
4. 有效期24小时，未来时间/过期/缺失/损坏/候选/旧commit/异仓库/部分job/资源不合格都拒绝。24小时是防长期复用的流程窗口，不是网络或性能稳定性的保证；相同commit改分支但不改tree可以复用，修改或新提交必须重新验证。
5. Git pre-push只读stdin中实际更新：仅接受当前已验收HEAD的分支更新、相同仓库和可证明的快进；新分支可接受，删除、标签、main、旧SHA、未知远端祖先均拒绝，需专项审核，不通过门禁隐式授权。无更新不产生远端写入，不伪称跑了回归。
6. `node scripts/install-hooks.mjs`仅修改本仓库local hooksPath；遇到已有其他hooksPath或活动pre-push不得覆盖。hook入库执行位必须正确，fresh clone需显式安装一次，本次在真实仓库安装后用`git hook run`验证，不实际Push。CI临时Git副本不复制源仓库配置，不能携入GitHub凭据或主机钩子。
7. 完整验证失败时不让上一份成功继续作为最新有效记录：旧报告保留，当前尝试先失效旧记录，失败保留对应报告，只有本次最终完整成功才能恢复有效记录。所有记录/制品留在.local，不把凭据或测试现场入Git。
8. 不改游戏业务、远端配置或分支保护；不强推、PR、远端重跑或部署。门禁通过仍必须展示完整提交列表、origin/master和实际结果后取得本次Push授权；最终云端必须观察同SHA，不承诺本地能复刻Azure内核/网络/负载。

## 验证
单元/临时Git仓库覆盖仓库规范化、HEAD/tree变动、时效、原始报告摘要、候选/部分job/缺race/不合格资源、重试/余量、零残留、实际refs/非快进，以及已有hook保护。运行真实Windows的Git hook检查但不Push；最终本地提交后通过同一共用入口重新完整验证真实source/race、test:ci和额外浏览器19例，生成只绑定该commit的记录，核对local master快进后仍有效。测试失败修复，不用伪造报告放行本仓库。

### 本地实现阶段结果
Windows运行器22/22通过；合成报告仅用于判据测试，临时Git仓库覆盖候选/部分job/缺race/资源/余量/原始报告字节/运行锁/旧HEAD/时效/非快进与已有hook保护，不能拿它们放行本仓库。真实本仓库已用`git hook run --to-stdin`验证缺少干净最终证据时退出1，未向任何远端Push。

首次正式运行在本地拒绝了3244040：Linux夹具只有Git索引100755、真实文件仍0644，被干净tree检查正确拒绝；Windows默认不跟踪文件执行位，单平台22项没有发现。已在夹具写入后实际chmod(0755)，不关闭filemode或删弱检查；真实Linux运行器21通过/Windows专有1跳过，Windows22通过。这是门禁推送前捕获的跨平台差异，失败保留，新commit继续完整验收。

正式记录必须在最终本地commit产生后，由同一真实共用入口完整执行并生成；这一步的事实读取`.local/push-verification.json`和其SHA绑定报告，不把候选或阶段22记录改成正式通过。记录缺失或验证失败都不能申请Push；同SHA的GitHub仍待另获授权后验收。

## 代价、迁移与回退
每次新提交都需十几分钟完整验收，文档-only暂不走捷径；缓存范围和环境不变，未做成本横评。Git本地hook可被用户绕过，不是远端安全边界，完整报告也不是第三方签名证明。安装不碰已有无关hook，默认不会跟克隆自动安装；规范明确检查安装状态。

回退仅将本仓库local hooksPath恢复安装前值，保留共用完整入口和每次授权，不自动删除其他hook/目录。若后续引入远端保护或共用镜像发布，需要另立决策并获明确授权。

## 重评条件
若频繁出现相同代码因网络/内核导致门禁失败，保留现场并区分准备/业务，不延长单例或加重试。若每次文档提交完整验收成本成为实际负担，再设计可测试的影响范围规则；在实测前不预造快车道。若需要防恶意绕过，再经授权增加远端保护，不将本地自证当安全承诺。
