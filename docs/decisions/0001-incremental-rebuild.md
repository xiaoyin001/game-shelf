# ADR-0001：从空仓库逐段形成可复跑成长历史

状态：采用。

## 背景
现有可玩版本满足本轮产品方向，但其骨架与可玩扩展各在一个大提交中，不能呈现规范、基础与玩法逐步形成的过程。本次目标是重新构建并逐阶段验证，不是恢复过去没有发生的开发历史。

## 比较
- 将旧大提交重新切片：快，但只是整理已有代码，不能证明每个中间阶段当时真实运行。
- 继续旧分支补文档：保留当前产品，但不能满足从零开始的要求。
- 保存旧版离线回退点，重新初始化空仓库，每段实现、验证后立即提交：采用，成本较高，但成长证据真实且可复跑。

## 决定
master 作为稳定交付分支，代码在 feat/rebuild-playable 开发。首先只有通用 AI 规则和无第三方依赖的 Node 规则测试，后续能力按需要增加；不一开始复制整套最终代码、报告或私人 AI 配置。

Node 内置测试足够验证文档入口、ADR 结构和追踪规则，当前不引入第三方测试框架。决策与文档直接入 Git，不沿用忽略整个 docs 的方式。

## 验证
首阶段执行 npm run check，校验必要入口、相对链接、ADR 字段和文档未被 Git 忽略。这个结果只证明规则可用，不能证明游戏可运行。

## 重评条件
每阶段都必须是可理解的小成果；若当前切分造成依赖不完整或无法验证，应调整切片边界并先记录原因，不用空提交凑数量。不回填旧时间、不改写已发布历史、不擅自远端写入。
