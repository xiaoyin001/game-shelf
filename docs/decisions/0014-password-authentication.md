# ADR-0014：以账号密码验证替代无密码试玩登录

状态：采用（本地 Windows/Linux 真实服务与 7/7 浏览器通过；3D 在下一阶段，远端未复验）。密码输入范围后由 [ADR-0016](0016-password-input-policy.md) 替代，下述 12–128 字符保留为原阶段历史。替代 ADR-0004 的无密码身份创建方式，保留四服务、单次凭据和同账号顶号。

## 背景
新增目标要求账号密码验证，并随后把 2D 客户端升级为 3D。现有 /login 仅按 channel:account 派生 user_id，经 db 写 players 即签发 token，任何人都可用同名进入，不能作为密码登录的基础。先独立交付可验证的注册/登录，再更换渲染，避免把安全与画面改动混成不可验收的大提交。

## 比较
- 明文或快速 SHA256 保存密码：不可抵御离线猜测，不采用。
- bcrypt：成熟，但有 72 字节输入限制，对长密码和中文需额外约束；不采用。
- Argon2id：采用现有 Go x/crypto，随机 16 字节盐，19MiB/2 次/1 路、32 字节输出，按 PHC 格式保存并恒定时间比较。成本未做生产基准，不承诺公网容量。
- 邮箱验证码、第三方身份或完整 OAuth 平台：当前不需要外部平台及凭据，不采用。

## 决定
1. 提供 /register 和 /login，必须同时提交账号和密码；注册成功可进入，之后必须验证密码，错误密码不签发 token、更不能顶掉在线会话。删除旧无密码/内部 upsert 身份入口，不提供兼容绕过开关。
2. 账号 NFKC 规范化并做 Unicode 大小写折叠，2–24 个字母/数字/下划线/连字符，按规范名唯一；展示名取首次注册的规范化原样。密码 12–128 字符、不截断、不去首尾空格，不接受控制字符或全空白。
3. db 是唯一凭据存储和验证入口。新 accounts 集合按规范账号使用 MongoDB 内置唯一 _id，新身份随机 user_id；旧 players 试玩记录原样保留、不绑定密码、不继承旧 ID。同名新注册是新身份，不能接管旧试玩记录。
4. 只保存带盐慢哈希，不保存/输出明文密码；认证消息 String 隐去凭据，回复只返回公共身份。未知账号与错密码返回相同错误，并进行等成本虚拟校验。
5. Argon2 工作并发上限 2；Redis 原子限制每 IP 120 次/分钟、每账号 12 次/分钟，TTL 自动回收。严格限制 JSON 大小、类型、尾随内容和跨站请求；凭据只在内存，页面不放 localStorage。
6. 复用已验收的 Redis 单次 token、原 TCP/WebSocket 认证和会话顶替。账号身份不再由 channel 决定，不能靠换 channel 绕过同账号策略。

## 代价、迁移与回退
旧试玩记录不自动升级，避免任何人用公开名字认领旧身份；可重新注册同名但获得新 ID。没有删除或覆盖旧数据。注册原子性由单个凭据文档保证，不要求 MongoDB 副本集或多文档事务。

页面继续只面向可信本机 HTTP；有密码不等于已具备公网账号安全。公网部署前还需 HTTPS、分布式滥用治理、密码重置和运维策略。本轮不实现邮箱/找回密码/MFA，不自动开放外网。回退只能回到明确隔离的试玩版本，不能把无密码入口作为新版兜底。

## 验证
阶段必须通过哈希/校验/规范化/边界单测，真实 MongoDB/Redis 上的注册、重复/并发注册、错密/未知账号/无密码拒绝、身份持久化、旧数据保护、限频、失败登录不顶号和正确顶号；保留全部协议和浏览器玩法。运行结果和未覆盖项随后记录，不能把 3D 计划称为已实现。

## 重评条件
需要外网、找回密码、跨设备长期会话或账号资产时，另立 ADR 补充威胁模型及迁移；哈希参数升级需限制解码成本并验证迁移，不能静默降低强度。
