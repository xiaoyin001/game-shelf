# ADR-0022：空闲渲染预算与分离 CI 环境/行为时限

状态：采用（2026-10-22，双CPU真实依赖/四服务/19项浏览器、独立协议与全量Go race通过；尚未补推/云端复验）。修正 [ADR-0015](0015-browser-3d.md) 的恒定30fps策略和 [ADR-0019](0019-npc-interactions.md) 的长委托浏览器流程，保留真实3D、权威玩法及 [ADR-0018](0018-browser-gather-ci.md) 的30秒/零重试原则。

## 背景与实际证据
提交516a117的 [CI39767562153](https://github.com/xiaoyin001/game-shelf/actions/runs/39767562153) source（含race）成功，真实依赖/全部协议通过，浏览器16/18通过。NPC委托与presence超30s，playable最终cancelled；GitHub annotation明确为“The job has exceeded the maximum execution time of 15m0s”。不是账号或物理断言失败的证据。

已下载的两份trace ZIP条目独立CRC校验通过（下载网络缓慢，未将不完整外层制品冒充完整下载）：NPC第二窗口填账号6.79s、等待真实重生10.44s、截图3.44s，领奖后约29.91s才点击重登，重进断言约30.67s结束；presence第二窗口填账号7.66s，重载后的填账号10.11s，行为断言约26.84s完成，在串行关闭上下文时超30s。DBus/mailbox噪声不作为根因。

CI安装日志另证实：官方apt下载19.7MB耗7m18s，安装浏览器工具整步约7m47s；这占用了全job的15分钟预算。原版在本地隔离工具容器仅限CPU0,1重跑，真实协议成功、17/18浏览器（4.1m），同一NPC用例再次30s超时；不是沿用未限制CPU时18/18的结果。

当前客户端在登录表单、静止角色、无操作的第二窗口也恒定每秒30次真实WebGL绘制，与表单/截图/关闭竞争CPU。具体性能改善尚未实测，需同样双CPU环境对比验证。

## 比较
- 提高Playwright单例时限、重试或跳过用例/关闭WebGL：不采用，会掩盖行为问题。
- 只改测试不降低静止场景的持续绘制：可以消除部分重复工作，但表单和其他已接近30s的用例仍无余量，不作为完整修复。
- 所有画面统一降低帧率或测试专用简化场景：不采用，损害移动/跳跃/镜头和真实场景验收。
- 只增加job总时限：无法修复两个30s失败，不采用为单独解决方案；但安装与业务需独立预算，避免网络慢让整个job在取证/清理阶段被终止。
- 按活动程度分配绘制预算 + 拆除长用例的等待耦合 + 独立环境/业务时限：采用。

## 决定
1. 普通用户和测试共用同一策略：角色有新位置/高度、加入离开、镜头/尺寸变化时保持30fps目标，最后变化后的750ms继续插值；静止/表单阶段12fps目标，火光/晶簇仍真实绘制，不冻结或用截图替代。网络输入/轮询仍100ms，权威物理不变。只读DOM记录实际绘制次数与调度模式供回归，不暴露改变状态的测试接口。
2. NPC完整双人委托仍验证接取、两次成功采集、领奖为5分、私有进度、关闭、退出/密码重登重置，但第二次通过探索另一现有晶簇完成，不让重生等待与完整剧情绑在同一30s用例。原来的真实重生/同地二次采集单独用一个完整浏览器用例保留，不能删掉10s重生验证。presence保留整页重载，两个独立上下文并行正常关闭且仍计入用例时限。
3. playable job总预算从15改25分钟，安装工具单步上限10分钟，真实完整test:ci单步上限12分钟，余量用于证据与退出；source不变，Playwright仍30s/零重试/单worker。总预算明确包含实际可见的网络安装耗时，不以此把浏览器失败变成通过，也不更换镜像/runner/数据库或修改远端配置。
4. 不动服务器玩法、现有试玩进程或开发账号数据；保持所有原断言与真实WebGL2/阴影、人物、晶簇和联机。旧选择保留，本次结果不能冒称云端复验成功，Push需新授权。

## 代价、迁移与回退
空闲装饰动画目标12fps，活动仍30fps；并非实际帧率保证或生产性能基准。新增一个聚焦冷却用例增加少量场景初始化，但避免单个用例承担两个独立生命周期。无数据迁移。可整套回退渲染/测试/预算；不能通过恢复恒定绘制后删断言来称回退成功。

## 验证计划
先检查规则/历史/源码/客户端；新增真实浏览器验证空闲仍绘制、次数预算、移动/镜头恢复活动模式，原双端跳跃/高度/步行等继续验证。使用与基线相同的CPU0,1独立网络/空tmpfs依赖重跑全部真实服务与浏览器，记录耗时、最慢用例与定向清理。Windows客户端检查、Linux全量race继续执行；完整test:ci、冷安装与远端CI若未执行必须明确标记，不以本地限核当云端通过。

## 实际验证
- Windows `check` / `check:client` / `test:runner`（6/6）、workflow Prettier、actionlint1.7.7通过。Linux工具容器仅分配CPU0,1、真实三依赖/四服务的 `check` / `check:client` / `test:all` / 独立 `test:services` / 全量Go race通过；最终19/19浏览器（3.9m），最慢NPC24.2s、重生15.3s、presence15.0s、扩展的3D用例21.3s。原版同限核环境为17/18（4.1m，NPC30s失败）。这是单机两轮观察，不是统计性能基准或云端同机复验。
- 实际GPU绘制计数证明空闲500ms窗口内仍有绘制且不超过12fps预算，镜头操作捕获活动模式；真实GL深度、双端移动/跳跃/迈步、原资源/委托/重登与上下文丢失全部通过，3D截图已查看。
- 首次修复版验证只跑到前两项便被本机WSL生命周期中断：三依赖正常退出、工具容器255/OOM=false；已保存现场，仅按本轮owner标签回收四个停止容器。此轮不记通过；前台持有本轮WSL保活后重新完整执行上述19项及race，最终本轮容器残留0。
- 未复跑冷环境apt安装、完整test:ci故障注入或新提交GitHub CI。job/step时限的语法与约束已验证，但不把这当作网络安装耗时保证；原15分钟取消结果未改写，等待新Push授权后观察新SHA。

## 重评条件
若新trace显示真实行为失败，修复行为而非继续加时；若空闲/活动预算仍不足，根据实际CPU/帧/接口耗时进一步优化。需要高刷新率、移动端功耗或规模指标时另立可实测预算，不凭单机时长宣称普遍性能提升。
