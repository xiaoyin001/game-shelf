# ADR-0016：6–32 位 ASCII 密码与前后端一致输入限制

状态：采用（Windows/Linux 真实服务、协议与各 11/11 浏览器通过；Go race 与资源回收通过；未 Push）。替代 [ADR-0014](0014-password-authentication.md) 的 12–128 字符密码输入范围，其余哈希、限频、身份和顶号策略保留。

## 背景
实际体验要求最低 6 位、缩小最大长度，并禁止中文密码，包括复制粘贴和绕过页面直接请求服务端。原实现允许 Unicode 和 128 字符，页面也没有最大长度，不能满足新要求。

## 比较
- 保留 12–128 字符或只改占位提示：不满足最低长度与实际校验要求，不采用。
- 6–32 位，只检查汉字：遗漏全角、表情、空白/不可见字符等输入法差异，前后端字符计数也容易不一致，不采用。
- 6–32 位 ASCII 可见字符（0x21–0x7e）：采用。英文字母、数字和英文符号均可，不强制混合；排除中文、其他非 ASCII 字符、空格和控制字符，字符数等于字节数。
- 静默删除非法字符或截断粘贴内容：会把用户的口令变成另一个口令，不采用。整次非法插入拒绝并提示，不发送认证请求。

## 决定
1. 注册和登录共用 6–32 位规则。Go 的 ValidatePassword 作为 HTTP 与 db 凭据存储的共同边界；非法密码在数据库读写、慢哈希和 token 签发之前拒绝。哈希成本、随机盐和限频不变；内部虚拟密码生成调整为符合新上限的随机值。
2. 页面提供 minlength/maxlength/pattern 和可见提示；键入和输入法提交由 input 校验兜底，粘贴在浏览器截断前整段校验，非法插入整次拒绝、不清理成另一个口令；非法尝试设置表单错误，直到合法编辑后才可提交。提交函数再做完整校验，不能仅依赖浏览器 HTML 属性。
3. 用户可以正常粘贴合法密码；不禁止密码管理器或复制粘贴本身。密码不裁剪、不规范化、不持久化，不在错误文字中回显。
4. 账号的 Unicode 规则不变。现存账号/哈希不改写、不清库；不符合新范围的旧密码也不再通过登录。单向哈希无法推断原密码并自动迁移；没有新增重置/找回后门，如需改现有账号密码须另行安全处理和授权。

## 代价、迁移与回退
6 位密码的抗猜测强度低于原最低 12 位；这是当前可信本机沙盒的体验取舍，不是公网密码策略建议。保留慢哈希与限频，仍禁止复用其他网站密码或直接开放公网。回退需要同时恢复前后端规则；不恢复无密码登录，也不自动删除或改写账号。对现有不合规密码的拒绝是明确的规则变化，不用静默截断或放行来掩盖。

## 验证
实际通过：5/6/32/33 位与全部 256 字节范围、中文/表情/全角/空格/控制字符边界单测；真实浏览器中文键入、真实剪贴板非法/合法粘贴、模拟输入法 input 分支和脚本提交；真实 HTTP 注册/登录及 db TCP 拒绝不合规密码，非法 HTTP 注册未落库。Windows 独立新卷 test:all 与 Linux 独立新卷 test:ci 均完成真实三依赖/四服务/全部协议和 11/11 浏览器；Go race、正常与故障资源回收通过。保留全部既有联机/3D 测试，不沿用阶段 15 的通过。

## 重评条件
需要公网、长期账号资产或找回密码时重新评估最低强度、泄露密码阻止与安全改密流程；扩大字符集或长度时必须重新验证前后端一致性及既有哈希，不做仅页面放宽。
