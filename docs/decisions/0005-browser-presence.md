# ADR-0005：浏览器接入与共享世界在线切片

状态：采用。

## 背景
登录与 TCP 大厅已通过。现在只实现两个独立浏览器进入同一张地图、观察在线角色、离开重进与同名顶替，暂不增加移动、聊天或采集。

## 比较
- Unity/Godot：适合更复杂的引擎内容，但当前可验收版本是浏览器 2D，增加编辑器和资源链没有直接收益。
- HTML + JavaScript + Canvas：采用，无客户端安装，AI 可以使用 DOM、键盘与浏览器上下文做确定性测试。
- React/Phaser：当前场景和表单较少，暂不引入框架。代价是手动维护小型页面状态。

浏览器不能访问原始 TCP。比较独立桥接进程、替换 TCP 与 gate 增加 WebSocket：采用第三种，保留现有 TCP 与内部 protobuf，仅浏览器边界使用带 version=1 的 JSON。
使用 coder/websocket 1.8.15，不手写握手与帧，context API 与现有超时策略一致。页面用 Go embed 嵌入 login，避免发布时资源路径不一致。

## 决定
lobby 的独立 world 模块拥有单世界状态；gate 不模拟玩法，只认证和转发身份。只有恰好一个 ready lobby 时允许接入，避免多实例把玩家分散到不同世界。
在线角色以会话租约维护，显式退出立即移除，异常退出最长 5 秒过期。消息有限长与频率，Origin 显式允许，浏览器不能传入 user_id 冒充身份。
新世界只提交已实现的进入/轮询/离开消息，后续玩法再演进，不预塞最终契约。
测试采用固定 Playwright 1.64.1 的双独立 context；开发格式工具采用 Prettier 3.6.2，仅开发依赖。Node 同一运行器托管服务与测试，finally 回收进程，不依赖手工终端。

## 验证
新增真实 Origin/凭据拒绝、在线状态、会话顶替和双浏览器进入/退出/重进；明确检查浏览器 pageerror。当前不声称支持移动、聊天或采集。

## 重评条件
需要 3D/原生客户端、多世界、跨机认证或大规模人数时再比较。100 个世界角色是防护上限，不是容量证明；位置为临时状态，不承诺长期资产。
