# ADR-0003：统一配置、发现与临时/长期存储边界

状态：采用；启动就绪判定部分由 [ADR-0011](0011-semantic-dependency-readiness.md) 补强，原存储与会话边界保持不变。

## 背景
通信库已独立通过。下一阶段先验证真实开发依赖及其公共封装，再加入业务进程，不一次装入整个服务骨架。

## 比较
- 全部使用内存：依赖少，但不能达到既有账号保存和会话一致性目标。
- 单一数据库兼任所有用途：部署简单，但会把长期账号和高频临时会话耦合。
- MongoDB 保存长期账号、Redis 保存过期凭据和会话、etcd 保存服务租约：采用，保持目标运行边界，代价是三种依赖。没有数据证明该组合比单体方案更高性能，当前不做扩容承诺。

配置使用标准 JSON 与 Go 类型，统一默认值、检查与时间单位，不引入新配置框架。日志使用 slog JSON；文件滚动使用既有 lumberjack 2.2.1，不手写滚动。配置变更观察只通知调用者，不宣称监听地址自动热切换。

## 决定
当前只增加通用基础设施模块、开发依赖启动器与真实烟测，不增加业务服务。
连接驱动固定 etcd 3.6.7、MongoDB v2.6.0、Redis 9.19.0，依赖产物由 go mod tidy 维护。
Redis key、TTL、单次 token 与原子会话替换只通过公共模块，旧会话不能删除新会话。
依赖仅绑定回环地址，命名卷保留，不清已有数据。

旧版本已暴露过 Windows WSL 空闲退出导致容器停止的问题。本次直接采用运行器自有的 WSL 前台管道保活，而不是假装重新发现：相比改全局 WSL 设置或要求人工开终端，只管理自有进程，退出关闭管道。不主动停止依赖或删除卷。

## 验证
规则与 Go 检查外，用真实 etcd 检查租约注册/发现，用 MongoDB 检查驱动连接，用 Redis 检查单次凭据、过期与原子顶替。普通包测试明确跳过需要依赖的烟测，npm run test:infra 单独启动依赖并执行真实烟测。不会把这一步写成登录或游戏已可用。

## 重评条件
需要减少本地依赖、引入长期进度或多实例容量时，另立 ADR 比较迁移与一致性。当前无业务服务，不提前设计世界分区或缓存层。
