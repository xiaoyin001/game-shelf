# ADR-0013：为 MongoDB 8.0.34 选择兼容的联机 CI 内核

状态：采用（本地实现与完整回归通过，尚未通过新提交的远端复验）。补充 ADR-0012，保留固定镜像、真实就绪、隔离数据和全部测试。

## 背景
[CI 39608598034](https://github.com/xiaoyin001/game-shelf/actions/runs/39608598034) 实际执行提交 662f9ae：source 成功，playable 在业务启动前失败。完整制品确认：
- 宿主为 Linux 7.0.0-1017-azure，MongoDB 8.0.34 容器退出码 1、OOMKilled=false。
- MongoDB 明确报告 6.19 及以上内核兼容问题 SERVER-121912，并主动退出；并非 TCP 等待或服务冷编译超时。
- 本地通过的 WSL 内核是 6.18.54.1，因此未触发这个内核条件。
- 失败前的容器状态、实际 digest、端口、日志已保存；随后本轮容器、卷、网络独立查询为 0。

这是本次失败的直接证据；第一次 CI 没有容器现场，不能据相似症状追认其最终根因。

## 比较
- 延长等待、重复跑相同提交：不能修复 MongoDB 主动拒绝启动，不采用。
- 用容器更换发行版但保留同一宿主内核：Docker 共享宿主内核，不能解决，不采用。
- 关闭内核检查或强制 rseq/分配器参数：不绕过数据库安全保护，不采用。
- 降级数据库或升级 MongoDB 大版本：改变现有数据库基线和驱动兼容范围；当前无需承担，不采用。
- 升级到官方 Ubuntu 内核修复版本：长期优先。[SERVER-131779](https://jira.mongodb.org/browse/SERVER-131779) 指定 8.0.35，但本次查询为未发布，官方 registry 的 8.0.35 tag 返回 404，不使用预发布或猜测标签。
- 仅将联机 job 临时固定到 Ubuntu 22.04，并检查实际内核：采用，保留 8.0.34 和全部真实回归；source 仍用 Ubuntu 24.04。

## 决定
1. playable 使用 ubuntu-22.04；[官方 runner 清单](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2204-Readme.md) 当前记录内核 6.8.0-1064-azure。清单不是实际运行证明，最终仍检查远端环境和完整结果。
2. CI 入口记录实际内核后，保守限制当前固定 MongoDB 组合使用 Linux <6.19；超出范围明确失败，不跳过数据库，不自动切镜像。此范围是本 CI 的已验收组合，不冒称所有 MongoDB 版本或所有 7.x 内核都不受支持。
3. Go、Node、Playwright、三数据库 digest、业务协议和六个浏览器用例均不变；本地补验 Ubuntu 22.04 用户态上的完整流程，远端必须再次以最终 SHA 实跑。

## 代价、迁移与回退
Ubuntu 22.04 是临时兼容方案：[GitHub 公告](https://github.com/actions/runner-images/issues/14254) 已进入弃用期，2027-03 起有 brownout，2027-04-17 退役，可能增加排队。最迟在 2027-02 或官方修复可用时重评，不把此方案当永久平台。

迁移只改联机 job 标签与内核前置检查，不迁移开发数据卷。回退或恢复 Ubuntu 24.04 必须先验证包含 SERVER-131779 修复的正式 MongoDB 镜像和实际宿主内核；不能只删前置检查或回退到已知失败组合。保留 ADR-0012 中已通过的隔离、就绪和故障取证机制。

## 验证
实际通过：Ubuntu 22.04.5 用户态、WSL 6.18.54.1 内核上的完整 test:ci（规则/历史/格式/源码、真实三依赖/四服务/协议、6/6 浏览器、故障清理）及全部包 Go race。内核范围及已有所有权保护共 5 个测试在 Linux 和 Windows 通过。普通 Windows 入口与业务代码未改，阶段 12 的真实回归仍适用，未重复执行 Windows 浏览器；不把旧运行说成本阶段重跑。实际云端内核与新 SHA 的 source/playable 仍待 Push 后验收。

## 重评条件
MongoDB 8.0.35+ 正式发布并验证 Ubuntu 内核修复时恢复较新 runner；若 22.04 实际内核也超出已验收范围，立即失败并按现场处理，不绕过保护。每次新提交 Push 和手动重跑仍分别取得具体授权。
