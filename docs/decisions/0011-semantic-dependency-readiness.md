# ADR-0011：依赖就绪改为真实协议检查并保留失败现场

状态：采用（本地准备，远端效果待复验）。替代 ADR-0003 中仅探测端口的启动就绪判定，不替换数据库或游戏架构。

## 背景
首次推送提交 4986865 后，[GitHub CI 39572389734](https://github.com/xiaoyin001/game-shelf/actions/runs/39572389734) 的 source 检查通过，playable 在起服阶段失败。DB 从 08:52:23 到 08:52:53 持续报告 MongoDB 127.0.0.1:27017 connection refused，尚未运行浏览器用例。

已证实启动器仅用 TCP connect 判断依赖就绪。端口代理能接通不等于 MongoDB 已能响应真实请求；仅保存业务进程日志也不足以解释容器为何对外不可达。此次未保存 Docker 容器状态与日志，MongoDB 不可达的最终原因尚无法确认，不能武断认定为启动慢、镜像问题或环境偶发。

## 比较
- 盲目重跑或放宽服务超时：可能偶然通过，但没有解决假就绪与证据缺失，不采用。
- 降级/更换 MongoDB 镜像：本机缓存与远端可变标签存在版本差异，但没有证据证明它导致故障，不据猜测更换。
- 启动业务前用现有 Go 驱动检查 MongoDB/Redis/etcd，并在失败时保存本项目 Compose 状态、镜像和容器日志：采用，能拒绝假就绪并给出后续定位所需证据。

## 决定
增加一次性 infra-check 工具，复用现有连接封装与 development.json 的启动等待配置，不增加业务端口、不写账号和游戏数据。
端口检查只用于占用/依赖启动判断；无论新启动还是复用已有依赖，都必须通过主机侧真实 MongoDB/Redis/etcd 协议检查后才启动四服务。
依赖检查或业务起服失败时，在回收自己的保活进程前保存 .local/logs/infra.log。诊断仅查看本项目 Compose，不停止服务、不清数据或卷。

## 验证
新增“TCP 可连接但不回应 MongoDB 协议必须失败”、真实就绪等待与取消回归；复跑本机真实依赖、完整四服务和全部浏览器用例。远端 CI 必须新运行复验，本地通过不能写成首次 CI 已修好。

## 重评条件
若复验仍失败，依据新容器日志继续定位，不继续猜测或堆叠超时。任何新的镜像、网络或运行环境调整另记录比较与验证；Push 和重跑 CI 仍单独授权。
