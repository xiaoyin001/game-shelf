# ADR-0028：私有依赖卷与已结束进程的等待计时器回收

状态：采用（2026-10-23，普通UID1001父进程及默认完整候选已通过；最终commit还需正式绑定记录，新SHA云端未通过）。接续 [ADR-0023](0023-shared-ci-preflight.md)、[ADR-0026](0026-ci-runner-ownership.md)；不增加12分钟运行/25分钟job或单例时限。

## 背景
ADR-0027路线修复候选的默认完整preflight源码/race及19/19＋额外新DB19/19均通过，最慢24.563s/22.8s，但第二轮退出末尾触及11分钟执行预算（12分钟留1分钟回收），整次正确失败、无推送记录。两轮项目及缓存都已定向回收；不能以浏览器全通过改判成功。

实际第一轮400.570s，其中npm ci 9.723s、test:ci 389.995s；第二轮在约260s末尾仍收尾，缺少余量。Windows的工具工作副本/依赖位于NTFS/DrvFS，Linux CI位于原生Unix文件系统，原设计把临时node_modules也反复放在宿主挂载目录。另stopStack的Promise.race在子进程快速退出时不取消5秒fallback，可能让Node无必要地继续存活；不是允许减少真实断言的理由。

## 比较
- 保持现状反复重跑择优，或加时/CPU/重试：不能解决余量与无效等待，不采用。
- 重复轮复用服务/数据库、跳过npm ci/原test:ci：削减冷启动或原覆盖，不采用。
- 全工作副本迁移Linux卷：可行但需新增源码/证据传输与生命周期，当前不扩大范围。
- 仅把node_modules放本job现有私有缓存卷，且及时取消已无需的退出计时器：采用。两轮仍各自npm ci，卷在job开始为空且结束删除，第二轮仍新Git副本/新DB/新服务，第一轮完整原回归不变。改前后的收益未实测，不承诺数字。

## 决定
1. 私有缓存初始化仅额外创建并chown该卷的node_modules子目录；SDK以volume-subpath挂到工作副本node_modules。root helper仍不挂工作副本，不改共享/开发目录；安装由宿主UID/GID完成。
2. 依赖挂载在source、playable及各平台共用；不复制宿主node_modules、不共用全局工具缓存，两轮npm ci原命令保持，不能借此跳过锁文件安装。
3. 提取有界waitForExit：已退出立即返回；正常退出或超时都移除监听/取消计时器，超时仍按原TERM→KILL。四服务及Windows保活子进程均用该函数，只处理已有明确归属的子进程。
4. 新子进程实测确保快速退出不被fallback留住；原超时/故障/WSL进程组及正常/故障回收覆盖保留。工具真实资源和所有预算不变。

## 代价、迁移与回退
要求已固定的新Docker支持volume-subpath；每job私有卷增加临时依赖树空间，结束回收，无持久数据迁移。若挂载失败则整次失败，可回退本变更并按原预算验收，不能不装依赖放行。计时器取消不降低等待期限，不改变产品进程终止协议。

## 重评条件
若依然触及预算，读取各步骤真实耗时后优化，不提高配额或减少原覆盖。若源码依赖需要特殊路径/跨挂载操作，新增实际回归再选择方案，不共享宿主依赖作默认缓存。
