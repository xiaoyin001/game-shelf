# ADR-0010：成长历史核对与 master 交付门槛

状态：采用。

## 背景
九个真实阶段已经分别实现、验证、提交，可玩能力和界面达到本轮验收对照。最后需要确认新历史确实从空仓库开始，验证成果没有遗漏，并将完整成果交付到 master。

## 比较
- 只展示最终截图或一次大提交：不能证明成长顺序和真实链路，不采用。
- 把所有历史版本另开 worktree 回放：增加工作副本与状态风险，不采用。
- 保留各阶段当次验证记录，额外检查 Git 对象中的阶段边界，再对最终源码完整重跑：采用；历史结构检查不冒充过去的测试执行。

## 决定
docs/history.json 固定本次重建的九个阶段提交及其当次验证命令，自动检查祖先顺序、空根与功能出现边界。后续可以追加正常提交，但不能把旧大提交放回成长序列。
最终执行规则/历史/格式/Go/真实依赖/协议/浏览器回归，以及 Linux Go race 与构建；分别说明证据和未覆盖项。归档产物不入库，文档检查排除依赖和测试产物，防止把失败现场 Markdown 当源码规范扫描。
相比只依赖本机命令或另建 Jenkins/其他 CI 平台，采用仓库所在平台的 GitHub Actions，无需增加独立常驻设施；动作权限仅 contents:read，不自动 Push 或创建 PR。工作流只新增定义，监听 master 与开发分支；checkout 获取完整历史以便核对。没有实际远端运行结果时，不写 CI 通过。
master 只快进到完整通过的开发提交，不 squash 掉本轮成长过程；Push 前仍需展示最终提交与 origin/master 目标并另行授权。

## 验证
本阶段运行 make check、check:client、test:all、独立 test:e2e、Linux Go race 与构建，并检查工作区、日志、进程和锁。实际结果写入验收记录；不复用旧仓库的报告。

## 重评条件
如果以后确需重写公开历史、切换主分支或改变验收环境，先记录新 ADR 与读者影响并取得对应授权。生产部署、大规模容量与公网安全仍不在本轮。
