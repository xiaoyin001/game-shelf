# ADR-0012：固定依赖、隔离数据并执行 Linux 冷启动 CI

状态：采用（固定镜像、隔离和完整回归继续有效；实际 CI 的内核不兼容与联机 runner 调整见 [ADR-0013](0013-mongodb-kernel-compatibility.md)）。补充 ADR-0011；原历史原因不猜测，最终候选以实际整套运行结果验收。

后续本地临时工具路线与云端原生安装发生偏差，共用有界工具入口由 [ADR-0023](0023-shared-ci-preflight.md) 和 [ADR-0024](0024-headless-ci-image.md) 接续；以下是原阶段的选择与真实当次结果。

## 背景
当前只有首次 master CI：source 通过，playable 在 MongoDB 不可达时起服失败。ed586de 增加了真实协议就绪和基础容器日志，但尚未证明干净 Linux 上完整起服与浏览器回归。

此前本机使用缓存镜像及旧数据卷，而 CI 使用新镜像与新数据；mongo:8.0、redis:7.4-alpine 和 ubuntu-latest 都会漂移。业务程序还按“编译一个、启动一个”串行进行，冷编译会混入进程启动期限。已知差异不足以确认旧故障根因，但必须消除这些不确定输入后验证最终候选。

## 比较
- 让 GitHub 访问开发者机器、私网 VM 或生产数据库：引入网络、凭据和共享数据依赖，不采用。
- GitHub Services：可以提供独立数据库，但会再维护一份三依赖配置，当前收益不足。
- Testcontainers：适合动态数据库矩阵，当前已有 Compose 与浏览器运行器，不为本次增加整套 SDK。
- 现有 Compose 加 CI 专用隔离配置、固定镜像、真实就绪与统一命令：采用，复用现有机制，本地 Linux 和远端运行同一逻辑。

## 决定
1. CI 使用 Ubuntu 24.04、Go 1.25.0、Node.js 22.23.3 与锁文件中的 Playwright 1.64.1。
2. CI 依赖使用明确补丁和 registry digest：MongoDB 8.0.34、Redis 7.4.11-alpine、etcd 3.5.18；不修改普通开发依赖的数据卷或把未知故障归咎于版本。
3. 每次 CI 使用唯一 Compose project 与新卷，不复用普通开发数据库；只清理本次自己创建的资源。
4. 先编译全部工具和业务二进制，再启动依赖，等待容器 health 与主机侧 Go 驱动协议检查，随后统一启动四服务。
5. 失败在清理前保存容器 State（含退出码/OOM）、实际镜像 digest、端口、日志；成功和失败均回收本次资源。
6. CI 使用统一 `npm run test:ci` 执行源码检查、真实依赖/协议、全部浏览器用例与失败清理回归，不跳过 MongoDB 或削弱测试。只下载默认 headless shell，省略未使用的 headed 浏览器；浏览器版本及 6 个既有用例不变。
7. 本地执行同版本 Linux 冷启动全套测试，远端仅在最终候选代码准备与本地验证完整后申请新 Push。真实 GitHub source/playable 全绿才完成本次目标。

本机验证使用现有 Ubuntu 24.04、校验过的 Node SDK 与项目私有浏览器/依赖目录，不全局升级 WSL 库，不创建额外 Git worktree。

本地工具准备曾尝试匹配版本的官方 Playwright 容器，但取层在 240 秒内没有完成；直接 WSL 浏览器下载同样停滞。因此改用从官方 HTTPS 下载的缓存，由原生 Playwright 安装器完成安装；缺失的系统库通过 apt 下载并只解包到项目忽略目录。缓存服务仅短暂监听本机回环并在安装结束回收，不伪造安装标记、不更换浏览器版本。这是本机下载路线调整，不修改 CI 的正常官方安装流程。

## 验证
- 两轮独立 Go 构建缓存、project 与空卷的 Linux 冷启动均通过真实依赖/协议及全部 6 个浏览器用例；当前统一入口的正向与失败清理回归通过。
- 失败回归仅替换本次子进程 PATH 中的编译工具，生成故意退出 23 的检查器；真实三依赖先完成 health，随后验证原错误、快照及容器/卷/网络为 0。备份和还原原有生成工具，不加入生产测试开关，也不把假检查器算作真实协议通过。
- scope/清理归属/注入拒绝和原占用保护共 4 个运行器测试通过；保留全部既有业务测试。
- Linux 完整源码/race、actionlint 1.7.7 工作流检查通过；Windows 在额外独立空卷上真实四服务、协议与浏览器 6/6 通过，WSL 诊断已实测。
- 原开发容器保持停止，原卷未删除、未用于上述测试；仅回收本次自建测试资源。
- GitHub 最终候选未推送/未运行，不能报告远端全通过；旧 CI 的最终原因仍未知。

## 代价、迁移与回退
固定 digest 需要主动维护补丁并重新验收；新卷与失败路径会增加下载/启动成本，未做成本基准测试。`test:ci` 只支持固定版本 Linux x64/AVX，普通 Windows 开发入口保留。Ubuntu 标签只固定发行版，GitHub 宿主镜像的内核和系统包仍可能滚动更新，并非位级环境锁定。

迁移只改 CI 使用专用 Compose 覆盖和统一命令，普通开发配置/卷不迁移。回退时撤销本阶段 CI 环境改造，保留 ADR-0011 的真实就绪检查与历史记录；回退后仍需完整验证，不能靠撤掉隔离、健康检查或测试获得绿色结果。

## 重评条件
若固定环境仍失败，按实际容器状态和协议失败阶段继续修复；不堆叠无依据超时，不降级或换服务来绕过失败。若必须调整镜像、资源或网络，再记录具体证据与取舍。每次额外远端写操作仍需确切范围授权。
