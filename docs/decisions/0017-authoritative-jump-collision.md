# ADR-0017：服务端跳跃与实体碰撞

状态：采用（Windows/Linux 最新真实服务、协议与各 14/14 浏览器通过，Go race 和资源回收通过；未 Push）。替代 [ADR-0015](0015-browser-3d.md) 的仅平面、无碰撞边界，保留四服务、真实 WebGL2 与账号/玩法。

## 背景
新增需求要求玩家跳跃、实体之间发生碰撞。原服务器只有 X/Y 位置，画面树木/岩石/营地仅在浏览器生成，玩家可相互穿透。仅播放弹跳动画或只在客户端阻挡不能保证联机一致与防绕过。

## 比较
- 客户端跳跃/碰撞：易被修改与双端分歧，不采用。
- 引入浏览器与 Go 两套完整刚体引擎：需额外 WASM/原生工具与跨引擎一致性，本轮不需要翻滚、物体破坏或复杂网格，不采用。
- 服务端有限范围的运动控制器：采用。竖直重力/落地使用小步长与扫过的高度区间，水平限速/小步碰撞与沿边滑动；角色圆柱，岩石/树/晶簇用圆柱包围体，帐篷用盒体，篝火按实体石圈/木柴体积处理。不是完整刚体或三角网格物理。
- 各端分别复制场景生成公式：易漂移，不采用。采用 Go 内嵌的单份场景 JSON，由同一客户端服务提供只读 /scene.json，前端据此绘制实体，后端据此判定碰撞。

## 决定
1. 空格发 jump 意图；只有站立在地面或实体顶面时才能起跳，松开再按，不处理键盘自动重复为连跳。客户端不提交高度、重力、速度或碰撞结果，伪造字段继续拒绝。
2. 服务端以自身时间推进所有角色的竖直运动，不依赖跳跃者继续发移动包；旁观轮询也能看到上升/落地。水平仍只承认最多 150ms 的输入额度，分为不超过 3 单位的小步，不能通过突发/空闲瞬移穿越。
3. 角色与角色、树木、岩石、帐篷、篝火实体、晶簇发生碰撞；晶簇冷却仍保留实体体积，画面只改变颜色/发光，不缩小制造空气墙；落到实体顶面可站立，离开支撑继续下落，空中不能再次起跳，地图地面与边界阻挡。湖面作为浅水地表，不实现游泳/浮力；路径、光、名牌和粒子不是实体。静态景物不受推挤、不翻滚，不新增战斗或动态破坏。
4. 出生位置同时检查实体、边界与角色，满员/没有安全位置明确失败，不把新角色放入障碍。采集距离包含高度，不允许远处或高空隔空采集。
5. 快照追加高度和站立标记、场景版本；服务器 X/Y/Z 对应 Three.js X/Z/Y。客户端插值真实模型高度、名牌与阴影，不模拟自己的权威轨迹。场景版本不一致必须提示重载，不使用无碰撞兜底。
6. 内部 protobuf 只追加字段，Go gate/lobby/客户端必须成套重建重启；原 TCP 大厅/认证、密码、聊天、采集、顶号、镜头、无 GL 拒绝保持回归。

## 代价、迁移与回退
包围体有少量几何近似，不承诺任意斜坡、动画骨骼、刚体冲量、移动平台或生产物理容量。物理单位延续原地图尺度，角色半径20/高度66，初速度380、重力800，平地最高约90，存在世界高度上限。场景和协议版本是本轮配套变更，不支持混用旧客户端。账号/哈希/持久化数据不迁移、不删除。回退须整套恢复匹配版本，不能仅取消服务端碰撞或恢复无密码入口。

## 验证
实际通过：跳跃轨迹/空中重复/停发输入仍落地、支撑/离开支撑/头顶接触/世界高度上限、玩家与五类实体碰撞/滑动/边界/安全出生、三维采集距离、快照独立复制、protobuf 往返及 1200 步混合动作不穿透单测。真实四服务双连接验证旁观者看到完整跳跃、碰撞后采集与冷却实体仍阻挡、跳过低矮实体、伪造高度关闭连接及唯一场景接口。Windows 独立新卷 test:all 的 14/14（1.1m）、Linux 独立新卷完整 test:ci 的 14/14（2.3m）、全量 Go race 和正常/故障清理均通过，真实跳跃/互撞截图已查看。一次短暂高度轮询遗漏经 trace 证实对端 DOM 实际出现高度；改为等待实际模型首帧、持续只读观察，不减少断言、增加重试或放宽 30s 用例限制。全部既有功能保留回归，新增提交未 Push，不沿用旧版本 CI。

## 重评条件
需要坡地、网格级碰撞、推箱、载具、复杂骨骼或更多动态物体时，重新比较服务端物理引擎与场景资产流程；规模预算须实测，不凭本机双人宣称支持大规模 MMO。
