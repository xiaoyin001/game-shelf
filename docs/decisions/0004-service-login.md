# ADR-0004：形成独立可运行的登录与 TCP 大厅链路

状态：四服务分工继续采用；无密码身份创建部分由 [ADR-0014](0014-password-authentication.md) 替代，以下保留原阶段的选择依据。

## 背景
通用通信和三种真实依赖已通过验证，现在需要第一个端到端业务切片：账号创建/读取、登录凭据、TCP 认证与大厅响应。还不加入浏览器或世界玩法。

## 比较
- 一个进程处理登录、连接、业务和数据库：部署简单，但会改变目标版本已有的分工和后续验证边界。
- login/gate/lobby/db 四进程：采用，HTTP 登录、长连接、业务与 MongoDB 写入口清晰，代价是本地需要组合起服。选择基于复现验收目标，不宣称它比单体容量更大。
- 为每个 HTTP 请求临时启动依赖：不采用，无法提供持续连接与可重复状态。

## 决定
login 提供 HTTP 开发登录并经 db 保存基础账号；gate 消费 Redis 单次 token 并建立会话；lobby 返回大厅数据；MongoDB 写入只在 db 内执行。开发账号无密码，只限可信本机/局域网，不作为生产账号系统。
当前仅增加四服务当前实际需要的契约和配置，不提前提交世界消息或 WebSocket。
运行器只管理自己创建的二进制、日志和锁；检测到占用端口立即失败，不复用未知旧服务；依赖和卷不清理。

## 验证
npm run test:services 从当前源码构建并启动四个真实服务，检查 ready，执行 HTTP -> db -> MongoDB 与 TCP 认证/心跳/大厅链路，再回收自建进程。另保留基础设施烟测。静态构建不能替代这些实际调用。

## 重评条件
当需要生产账号、跨机安全、可靠单端策略或大规模路由时，必须另立 ADR 比较与验证。当前 HTTP 开发登录不开放互联网；这个阶段不称为可玩游戏。
