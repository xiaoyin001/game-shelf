# ADR-0034：按几何部位批处理真实角色

状态：采用（2026-10-27，先决策后实现；Windows真实服务/21例、源码/客户端检查与全量Go race通过；随后49e4822默认完整门禁source/race与协议通过，但浏览器20/21，仍未交付master或Push）。接续[ADR-0033](0033-static-batching-and-ui-updates.md)，不改变玩法、物理、角色外观、材质/阴影、30/12fps、分辨率或验收门禁。

## 背景
静态石头/界面切片78b44c6已在Windows和固定SDK双CPU Linux单playable各21/21通过，但候选13f1d00c的展台29.563秒仍高于默认27秒余量，单轮约5.0m也不足以保证两轮总预算。当前仍无最终推送证明，不能用单job成功放行。

## 比较
- 保持每位玩家/NPC的10个独立身体mesh及独立圆环：代码直观，但双人加两位NPC时存在重复几何/材质绘制调用，不采用。
- 降低帧率、画质、阴影、分辨率，暂停后台窗口或放宽测试：改变真实体验或门禁，不采用。
- 用Three.js既有InstancedMesh按body/head/eye/cap/limb/bag/ring七种几何批处理，保留各角色的真实变换与实例颜色：采用。无需新库、骨骼或离线模型；结构上从多个重复draw降为七个部位批次，不预先宣称实测提速。

## 决定
1. 维持原身体、头、眼、帽、四肢和背包几何、颜色、局部位置、透明圆环与文字名牌；仍使用Lambert光照、实际深度和原阴影。两条腿仍按原节奏反向摆动，每个局部部件由角色世界矩阵产生实例矩阵，不用贴图、截图或冻结模型代替。
2. 同几何部位共享白色基础材质并使用原RGB实例颜色；名牌继续独立Sprite，不更改NPC身份或玩家人数。实例缓冲容量仅覆盖当前世界实际支持的100位玩家加固定NPC，mesh.count始终是本帧真实数量，不绘制占位角色，不宣称已做100人GPU容量验收。
3. 权威位置/高度仍来自服务器，客户端原插值/镜头和活动调度不变。NPC/玩家保留位置与局部姿态锚点，绘制前把真实部件矩阵写入实例缓冲；加入/离开更新实际实例数量，文字资源正常释放，不能移除其他角色所共享的几何。
4. 只读selfHeight改从本帧真实身体实例矩阵扣除原局部身体高度25得到，不以不含几何的空锚点冒充可见模型；追加实际角色实例数/七部位批次数观察。原角色首帧、跳跃、低台阶、对端同步、镜头、GL深度与失去上下文断开回归继续保留。
5. 动态实例批次禁用静态对象级视锥裁剪，保证角色移动不依赖过期包围球而消失；GPU仍执行正常裁剪与深度。实际数量有界，未做大规模性能横评。不增加新配置、不改SDK/CI运行器/资源或30秒/27秒/零重试与总预算。

## 验证
- Windows check:workflow/check/check:client、真实test:all全部21例与全量Go race；查看新的双人、NPC、跳跃/台阶、营火/石头/展台截图，确认体型/颜色/动作保持。
- 浏览器从真实WebGL绘制观察四位角色实例及七批次；保留本帧实例高度和所有原物理/渲染断言。实例数量必须随真实在线/退出改变，不允许可写调试入口。
- 完整相关回归通过后本地阶段提交；最终干净HEAD必须默认完整verify:ci（source/race、完整真实协议/全部21例及额外新DB21例/正常故障回收）通过并生成绑定证据，再核对真实pre-push后普通快进Push并观察同SHA CI。候选单job、旧tree或本地Windows仍不能替代。

## 代价、迁移与回退
增加实例矩阵与颜色映射维护，需防止角色顺序变化引起错色/错位；每帧写入少量有界实例缓冲。动态部位不再能各自以mesh做场景查询，当前交互权威仍在Go端，不依赖客户端射线命中。无账号/存档迁移，回退前一客户端仍兼容schema2；未实测统计性能或成本。

## 重评条件
模型/高度错位、动态阴影或角色颜色不一致、离开残影、严格全量回归/预算仍失败时依据本轮现场继续修复；需要蒙皮动画/装备/更大规模时另评资源与角色渲染方案，不以关闭真实图形或降低门禁放行。
